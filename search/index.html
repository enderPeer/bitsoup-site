Search

The other half of the project. The world pays organisms for answering tasks, small functions of two numbers. How hard is a task to hit by chance, what is the shortest program for it, and can a guesser that has learned from short programs find longer ones faster, without ever being wrong?

The machine

A program is a sequence of the 14 instructions of the soup's machine that touch only the registers and the stack: inca incb decc zeroc subab subac movba nand pusha popa pushb popb pushc popc. It starts with the two inputs in two registers, the third at zero and an empty stack. Its answer is the low 4 bits of the first register, and the function it computes is its answer on all 256 pairs of 4-bit inputs. Two programs compute the same function when those 256 answers agree.

The sweep: what a task costs

Every program of up to 7 instructions, 113,522,235 of them, was run on all 256 input pairs. They compute 6,167 different functions, 12 of them constant. Up to 8 instructions it is 1,589,311,291 programs and 25,768 functions. The price of a task is how many bits of luck a random program needs to compute it: log₂ of all programs over the programs that compute it. The world pays its tasks by the prices at 7; a task that no program of that length computes was priced by hand.

The search: the shortest program, with a proof

The search does not run every program. It keeps one entry per state the machine can be in, level by level, because two programs that leave the same registers and stack behave alike whatever follows. A function first met at length n has no shorter program; one never met has none within the range. Past what fits in memory it runs every tail of instructions from the last stored level, storing nothing, and the counts stay exact. So it has covered every program of up to 12 instructions, 61,054,982,558,011 of them. The proofs hold for 4-bit inputs.

a*b: no program of up to 14 instructions, searched alone. a*a: no program of up to 14 instructions, searched alone.

Six of the tasks without a program, a>>1, a==b, a<b, max, min and popcount, cannot be computed by these 14 instructions at any length: with them, a bit of the answer depends only on the same and lower bits of the inputs, and each of the six needs a lower bit that depends on a higher one. a*b and a*a do not, so they may still appear at greater lengths. Organisms are not limited to these instructions: ifz and the jumps let a program branch.

Jumps: do they make a program shorter?

Organisms can branch and loop: ifz skips an instruction, and jmpf and jmpb jump forward or back to a template of nop0 and nop1. Every program of up to 8 instructions over these 19 was run for at most 64 steps: 151,903,898 programs, of which 64,373,182 stopped and 87,530,716 were still running.

No function has a shorter program with jumps than without, among the 647 that programs with jumps compute. 34 functions are reached only with jumps, by loops of 8 instructions such as subab nop0 popc pusha inca ifz jmpb nop1; none of them is a task. A second program, written apart, checks these counts.

A guesser beside the search

The guessers learn from the shortest programs of up to 8 instructions, step by step: given the target function and the program so far, which instruction comes next. One function in ten is held out whole and used only for testing. A guesser only orders the search; every program found is checked on all 256 input pairs, by the search and again in the soup's own interpreter. So a guesser can make the search slow, never wrong.

4-bit a*b and a*a: none of the reference run's searches found a program for either. The exhaustive search proves that a*b has none of up to 14 instructions; a*a has none of up to 14 instructions, and a longer search for it alone found one of 15, so its shortest has 15 to 15. That program is not an answer the world pays: the world asks its tasks with 16-bit numbers and checks all 16 bits, and on 16-bit inputs it is wrong on 4,087 of 4,096 random pairs.

Found: within a fixed budget per target, 50,000 expansions or 300,000,000 programs. Work is counted in different units: an expansion of the state search makes 14 successor states and stores them; a program of the depth-first search is one step and stores nothing. Compare within an engine, not across. "Times fewer than blind" is, for the state search, against the blind search over states, whose work is known exactly from the catalogue; for the depth-first search it is a lower bound, against the fewest programs a search in uniform order must try before reaching that length. Both searches go by probability, not by length, so a program found can be longer than the shortest; in range and one past, the shortest length is known exactly. Beyond, only an interval is known: no program within the exhaustive range exists, and the program found is one example. A program counts as wrong if it fails on any of the 256 input pairs, checked by the search and again in the soup's own interpreter, or if it is shorter than proven possible.

Life from random bytes

Does life start from random bytes under the world's rules? In the world an organism is made only by genesis, division or arrival, so bytes nobody owns are never run. A bench beside the world strikes sparks: a processor started on a stretch of a region's own random bytes, with a reserve of energy, in the sandbox's sealed standard region. A spark counts when a living member of its line, other than the spark itself, has the spark's bytes.

No spark has copied itself: none of 78.8 million sparks under the present rules and none of 12.3 million under rules 5. Some lines divide, but no daughter has the spark's bytes.
